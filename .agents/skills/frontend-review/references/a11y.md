# accessibility best practices

## Abstract
Focus on:

1. **Semantic HTML correctness**
2. **Keyboard accessibility**
3. **Screen reader compatibility**
4. **ARIA correctness (only when necessary)**

## Core Review Rules

### 1. Use Semantic HTML First
**Impact: Critical**
Flag:

- Overuse of `<div>` / `<span>` for interactive or structural elements
- Replacing native elements with custom equivalents

Prefer:

- `<button>` instead of clickable `<div>`
- `<a>` for navigation
- `<label>` + `<input>` pairing
- `<nav>`, `<main>`, `<section>`, `<article>`, `<header>`, `<footer>`

---

### 2. Interactive Elements Must Be Accessible
**Impact: Critical**
For any interactive element:

- Must be **focusable**
- Must be usable via **keyboard**

Flag:

- `onClick` on non-interactive elements
- Missing `tabindex` when needed
- No keyboard handlers (`Enter`, `Space`)

Prefer:

- Native elements over ARIA recreation
- If custom:
  - `role`
  - `tabindex="0"`
  - keyboard event handling

---

### 3. Labels and Form Accessibility
**Impact: Critical**
Every form control must have:

- A visible or programmatic label

Flag:

- Inputs without `<label>`
- Placeholder used as label
- Missing `id` ↔ `for` association

Prefer:

```html
<label for="email">Email</label>
<input id="email" type="email" />
```

### 4. Accessible Names
**Impact: Critical**
Ensure all interactive elements have a clear accessible name.

Flag:

- Icon-only buttons without labels
- Ambiguous link text (“click here”)

Prefer:

- aria-label when no visible text
- descriptive text content

### 5. ARIA Usage (Strict)
**Impact: High**
Principle:

No ARIA is better than bad ARIA.

Flag:

- Incorrect roles
- Redundant roles on native elements
- Misuse of aria-*

Prefer:

- Native HTML first
- ARIA only when necessary

### 6. Heading Structure
**Impact: Medium**
Check:

- Logical heading hierarchy (h1 → h2 → h3)
- No skipped levels

Flag:

- Using headings for styling only
- Multiple h1 without structure context (if not intentional)

### 7. Keyboard Navigation
**Impact: High**
Ensure:

- All interactive elements reachable via Tab
- Logical tab order
- No keyboard traps

Flag:

- Elements not focusable but interactive
- Broken tab flow

### 8. Focus Management
**Impact: High**
Check:

- Visible focus states (not removed)
- Proper focus handling in modals/dialogs

Flag:

- outline: none without replacement
- Focus lost on interaction
- No focus trap in modal

### 9. Images and Media
**Impact: Critical**
Require:

- alt for all meaningful images

Flag:

- Missing alt
- Redundant alt text (“image of…”)
- Decorative images not marked properly

Prefer:

- alt="" for decorative images

### 10. Links and Navigation
**Impact: High**
Flag:

- Non-descriptive link text
- Click handlers on non-link elements for navigation

Prefer:

- `<a href="...">` for navigation
- Clear, descriptive link labels

### 11. Color and Visual Dependence
**Impact: Critical**
Flag:

- Meaning conveyed by color only
- Missing non-visual cues

Prefer:

- text + icon + structure

### 12. Dynamic Content & State
**Impact: High**
Check:

- UI updates announced to screen readers when necessary

Flag:

- Hidden state changes not communicated
- Missing aria-live where appropriate
- Anti-Patterns to Call Out Explicitly
- Clickable `<div>` instead of `<button>`
- Placeholder as label
- Misused ARIA roles
- Removing focus outlines
- Ignoring keyboard interaction
- Icon-only controls without labels
